# 출근 기록 — 안드로이드 설치형 앱

홈 화면에 설치되고, 신호가 없어도 동작하는 PWA입니다.
파일 6개를 그대로 올리기만 하면 돼요.

```
index.html
manifest.webmanifest
sw.js
icon-192.png
icon-512.png
icon-maskable-512.png
```

---

## 왜 토스 미니앱이 아닌가

토스로 만들어도 매일 쓰면서 테스트하는 건 심사를 통과한 뒤에야 가능해요.
그리고 정작 신경 쓰이는 마찰 — 잠금 해제하고 태그를 대는 동작 — 은 토스 쪽이 더 깁니다.
`토스 실행 → 미니앱 로딩`이 한 단계 더 붙거든요.

설치형 PWA로 만들면 실제 앱과 체감 차이가 거의 없습니다.

| | 웹페이지 | 설치형 PWA | 토스 미니앱 |
|---|---|---|---|
| 홈 화면 아이콘 | ✗ | ✓ | 토스 안에서만 |
| 주소창 없는 전체화면 | ✗ | ✓ | ✓ |
| 신호 없을 때 | 로딩 실패 | **동작** | 로딩 실패 |
| 태그 → 실행 속도 | 보통 | **가장 빠름** | 가장 느림 |
| 오늘 쓸 수 있나 | ✓ | ✓ | ✗ (심사 필요) |

---

## 1. 올리기

HTTPS가 필수예요. NFC 태그 쓰기와 서비스워커가 HTTPS에서만 동작합니다.

**GitHub Pages**
1. public 저장소를 만들고 위 6개 파일을 루트에 올려요. (폴더 안이 아니라 루트)
2. Settings → Pages → Source를 `main` 브랜치 루트로.
3. `https://<아이디>.github.io/<저장소>/` 로 열립니다.

Netlify Drop(`app.netlify.com/drop`)에 폴더째 끌어다 놓아도 됩니다.

---

## 2. 설치

1. 안드로이드 **크롬**으로 주소를 엽니다.
2. 상단에 뜨는 **홈 화면에 설치하기** 배너에서 `설치`를 누릅니다.
   (안 뜨면 크롬 메뉴 → `앱 설치` 또는 `홈 화면에 추가`)
3. 홈 화면에 아이콘이 생기고, 이때부터 앱처럼 전체화면으로 열려요.

설치하면 부수 효과가 두 개 생깁니다.
- NFC 태그를 찍으면 크롬 탭이 아니라 **설치된 앱**이 바로 열려요. "어떤 앱으로 열까요?" 프롬프트 부담이 줄어듭니다.
- 아이콘을 **길게 누르면** `집 출발 기록 / 버스 탑승 기록 / 회사 도착 기록` 바로가기가 나와요.
  NFC 태그를 깜빡했거나 태그가 손에 없을 때 대안이 됩니다.

---

## 3. 태그 만들기

빈 NFC 태그(NTAG213 이상) 3개가 필요해요.

앱의 **NFC 태그** 섹션에서 `태그에 쓰기`를 누르고 3초 안에 태그를 휴대폰 뒷면에 대면 끝입니다.
크롬이 아니거나 실패하면 `주소 복사` → **NFC Tools** 앱의 `WRITE → Add a record → URL/URI`에 붙여넣으세요.

**붙일 위치**
- 집 출발 → 현관문 안쪽
- 버스 탑승 → 카드지갑 / 사원증 케이스 안쪽 (버스에는 못 붙이니까)
- 회사 도착 → 책상 모서리

---

## 4. 테스트 체크리스트

| 확인 | 무엇을 보나 | 실패하면 |
|---|---|---|
| 1. 인식 | 태그를 댔을 때 반응하는가 | 설정 → 연결 → NFC → **NFC 태그 읽기/쓰기** 켜기. 기본 모드가 `카드 모드`면 태그를 못 읽어요 |
| 2. 열리는 곳 | 크롬 탭이 아니라 설치된 앱으로 열리는가 | 설치를 다시 확인. 프롬프트가 뜨면 앱을 고르고 `항상` |
| 3. 오프라인 | **비행기 모드로 바꾼 뒤** 태그 찍기 | 화면 상단에 `오프라인`이 뜨면서도 기록돼야 정상 |
| 4. 중복 방지 | 같은 태그 연속 두 번 | "이미 기록됨"이 떠야 정상. 2분 안의 재태그는 저장 안 함 |
| 5. 잠금화면 | 화면 끈 상태로 태그 | 대부분 기기는 화면이 켜져 있어야 읽어요 |

**5번이 여전히 유일한 진짜 관문입니다.** 이건 PWA로도 토스로도 해결이 안 돼요.
안드로이드 OS 정책이라서요. 주머니에서 폰 꺼내 → 화면 켜고 → 태그 대는 3동작을
일주일 견딜 만한지가 이 방식이 살아남을지의 기준입니다.

만약 이게 거슬린다면, 태그를 포기하고 홈 화면 아이콘 길게 누르기(3번 항목의 바로가기)로
기록하는 쪽이 실제로는 더 빠를 수도 있어요. 둘 다 써보고 비교해 보세요.

---

## 5. 쌓이는 데이터

- 구간별 소요시간 (출발→버스, 버스→회사, 총 출근시간)
- 최근 14일 기록
- **완결된 날이 5일 이상** 모이면 패턴 분석이 열려요. 출발 시각 중앙값을 기준으로
  그 전/후에 나간 날의 평균 소요시간을 비교합니다.

5일 미만에서는 아무 주장도 하지 않아요. 3일치로 패턴을 말하는 건 의미가 없어서요.

기록은 **그 기기에만** 저장됩니다. 서버가 없어요.
앱을 지우거나 사이트 데이터를 삭제하면 사라지니 주 1회 CSV로 내보내 두세요.

## 6. 나중에 토스로 옮길 때

앱인토스 WebView SDK는 기존 웹 서비스를 감싸는 방식이라 이 코드를 거의 그대로 씁니다.
콘솔에서 앱 이름을 받은 뒤 `granite.config.ts`만 추가하면 돼요.

```ts
import { defineConfig } from '@apps-in-toss/web-framework/config';

export default defineConfig({
  appName: 'commute-log',          // 콘솔에서 발급받은 이름
  brand: {
    displayName: '출근 기록',
    primaryColor: '#FFB44D',
  },
});
```

그러면 태그 주소가 `https://...?event=bus_board` 에서
`intoss://commute-log?event=bus_board` 로 바뀝니다. `?event=` 를 읽는 코드는 그대로예요.

단, 토스 안에서는 서비스워커가 동작하지 않을 가능성이 높아 오프라인 이점은 사라집니다.
그 점까지 감안해서 옮길지 결정하세요.

## 알려진 제약

- 태그 접촉과 저장 시각 사이 1~2초 오차. 출근 분석에서는 무시 가능한 수준이에요.
- 화면이 꺼진 상태에서는 태그를 못 읽는 기기가 많아요.
- 태그 쓰기(Web NFC)는 안드로이드 크롬 전용. 읽기는 모든 기기에서 됩니다.
- 새벽 4시 이전 기록은 전날로 묶여요. 아침 출근 기준이라서요.
- 코드를 수정해 다시 올리면 `sw.js` 안의 `commute-shell-v1` 을 `v2`로 바꿔야 캐시가 갱신됩니다.
